# Enable event enthusiasm responses

The sibling `samfunnetibergen` website uses the signed API in `app/api/v1/event_interest.py` to store capped enthusiasm responses in this backend's existing Postgres database. Event content and visibility remain owned by Sanity in the website; the backend stores an opaque event document ID, an event-specific source digest, tap count, and expiry. This does not restore `/api/v1/events`.

Apply `migrations/versions/20261001_1400_event_interest.py` through the normal migration process. Configure a matching random `EVENT_INTEREST_SECRET` of at least 32 characters on the website and this backend. Generate it with `openssl rand -hex 32`, store it in server environments, and never expose it in client settings. The website calls the backend URL from `PERSONAL_APP_BASE_URL`. Deploy the backend before the website.

POST `/api/v1/event-interest/read` accepts `{event_id, source_hash}`; the source digest may be null. POST `/api/v1/event-interest/response` also requires `taps`, an integer 0–12. Both return `{taps, score}` and forbid caching. Write count zero deletes the response. A source contributes 0.25 points at 1–3 taps, 0.75 at 4–7, and 1 at 8–12. Writes keep the greatest count so retrying older cumulative counts is safe. The website serializes its requests and initializes a signed event cookie before sending any response writes. An event-level transaction lock makes concurrent writes and totals consistent.

All calls require HMAC authentication: headers `X-Kvarteret-Timestamp`, `X-Kvarteret-Nonce` (a UUID), and `X-Kvarteret-Signature` (`v1=<hex>`). The canonical signed value is `event-interest-v1`, timestamp, nonce, HTTP method, request path, and SHA256 hex digest of the exact body bytes, joined with newlines. Authentication uses `EVENT_INTEREST_SECRET`; timestamp tolerance is five minutes. Nonces cannot be reused within ten minutes. A global 3000-request-per-minute limit protects this service without storing IP addresses. The website validates event publication and status before calling this backend; direct callers without the server secret are rejected.

Schedule `uv run python -m scripts.cleanup_event_interest` daily using the existing backend job runner and environment. It deletes rows after their fixed 90-day expiry. Reads always exclude expired responses, and active writes prune expired responses for that event. The table enables RLS with no public policies and revokes PUBLIC access; use the backend's existing owner/service database connection.

Cookie grouping represents browsers rather than verified people. Clearing cookies or switching browsers can produce another contribution. No account or volunteer records are linked, and no IP/fingerprint is used in this feature. Rotating the shared secret invalidates website cookies while old contributions remain until expiry. The website includes an explanation and a removal control. See the sibling website's `docs/how-to/event-interest.md` for browser behavior, privacy scope and rollout checks.

Run `uv run pytest tests/api/event_interest` for auth and validation. To include real persistence/concurrency checks, set `EVENT_INTEREST_TEST_DATABASE_URL` to a disposable PostgreSQL connection string using the `postgresql+asyncpg` scheme. Regenerate OpenAPI with `uv run python -m scripts.export_openapi` and verify with the same command plus `--check`.
